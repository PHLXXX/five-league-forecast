# 五大联赛分析平台设计规格

## 目标

将现有世界杯分析工具升级为仅覆盖英超、法甲、德甲、西甲、意甲的统一赛事分析平台。产品覆盖当前赛季完整赛程、积分榜、完场赛果、赛前推荐保存、推荐结算和完整历史回测，并保留胜平负、比分、让球、大小球、角球、罚牌、体彩推荐和比赛模拟等现有能力。

世界杯赛程、FIFA 国家队排名、世界杯专用数据源、世界杯搜索词和世界杯历史统计不再出现在产品、接口或有效统计中。旧数据在迁移前生成本地备份，但不继续参与运行时逻辑。

## 赛事范围

| 联赛 | 中文名 | football-data 代码 | ESPN 代码 |
| --- | --- | --- | --- |
| Premier League | 英超 | `PL` | `eng.1` |
| Ligue 1 | 法甲 | `FL1` | `fra.1` |
| Bundesliga | 德甲 | `BL1` | `ger.1` |
| Primera Division | 西甲 | `PD` | `esp.1` |
| Serie A | 意甲 | `SA` | `ita.1` |

赛季必须由数据源动态识别，不把 `2026` 固定写入业务逻辑。界面默认选择当前赛季和未来七天赛程，同时允许浏览整个赛季、已完场、未开赛和按日期筛选。

## 产品结构

采用“统一平台 + 联赛配置”的架构。五个联赛共享数据标准化、分析、预测、盘口、模拟和回测代码，通过赛事配置提供不同的数据源代码、中文名称、旗标、颜色和模型校准参数。

主界面包含：

1. 顶部联赛切换与赛季选择。
2. 左侧日期、球队、比赛状态筛选及当轮比赛列表。
3. 中央比赛分析区，继续展示比分概率、胜平负、大小球、让球、角球、罚牌、体彩和比赛模拟。
4. 联赛积分榜、近期走势和主客场表现。
5. 历史回测中心，可按联赛、赛季、玩法和日期筛选。

所有面向用户的内容使用中文。球队、球场和球员名称优先使用稳定中文映射；没有可靠中文名时保留官方名称并标记来源，不进行不确定的机器臆译。

## 后端架构

新增赛事配置模块，作为所有数据请求的唯一赛事入口。配置项至少包含：

- `id`：内部稳定标识。
- `nameZh`、`nameEn`：中英文名称。
- `footballDataCode`、`espnSlug`：结构化数据源代码。
- `countryCode`：队徽和地区显示。
- `seasonRules`：赛季边界与轮次规则。
- `modelProfile`：主场优势、联赛进球均值、角球和罚牌基线。

数据层拆分为赛事目录、赛程、积分榜、球队状态和盘口适配器。接口统一输出标准比赛对象：

```json
{
  "id": "PL:2026:12345",
  "competitionId": "PL",
  "season": 2026,
  "matchday": 12,
  "kickoffUtc": "2026-11-08T16:30:00Z",
  "kickoffBeijing": "2026-11-09T00:30:00+08:00",
  "status": "SCHEDULED",
  "home": {},
  "away": {},
  "score": null,
  "venue": {}
}
```

比赛 ID 必须带联赛命名空间，禁止不同数据源或不同联赛的数字 ID 相互覆盖。别名只可在同一联赛、同一日期和相同对阵间建立。

## 数据来源与缓存

结构化数据优先级：

1. football-data.org：赛季、赛程、结果、积分榜、球队和名单。
2. ESPN 五大联赛端点：赛果核验、技术统计、赛事事件和赔率摘要。
3. 中国体彩网：官方受注场次及胜平负、让球胜平负、总进球和比分。
4. Pinnacle 和可验证盘口来源：胜平负、让球、大小球、角球、罚牌。
5. Open-Meteo 与场馆地理数据：比赛当地天气和海拔。
6. 可信赛事媒体与球队官方消息：24 小时情报、伤停、停赛、轮换和预计战术。

赛程和积分榜使用按联赛、赛季分区的缓存；比赛分析使用按比赛 ID 分区的快速缓存和深度缓存。接口先返回快速结构化结果，再在后台更新网页情报和衍生盘口，避免切换场次时长时间空白。

## API

- `GET /api/competitions`：五大联赛及可用赛季。
- `GET /api/matches?competition=PL&season=2026&status=all`：指定联赛整季赛程。
- `GET /api/standings?competition=PL&season=2026`：总榜、主场榜和客场榜。
- `GET /api/analyze?matchId=PL:2026:12345&quick=1`：快速分析。
- `GET /api/analyze?matchId=PL:2026:12345&depth=balanced`：深度分析。
- `GET /api/history?competition=PL&season=2026&market=score`：保存推荐统计。
- `GET /api/backtest?competition=PL&season=2026&market=score`：离线历史回测。

原有接口在迁移期保留兼容形式，但不再返回世界杯比赛。

## 预测与模拟

国家队 FIFA 排名因子由俱乐部强度体系替代。模型输入包括：

- 当前积分、净胜球、每场积分和联赛排名。
- 最近 5 场与最近 10 场状态。
- 主队主场、客队客场的进失球表现。
- 同联赛对手强度修正后的攻防效率。
- 历史交锋，但对陈旧交锋降低权重。
- 伤停、停赛、预计轮换和赛程密度。
- 盘口隐含概率和多源市场一致度。
- 天气、球场、旅行和休息天数。

先生成统一的主客队期望进球、胜平负概率和比分概率矩阵，再由同一结果派生比分、让球、大小球和双方进球推荐。事件模拟使用相同的球队强度与比赛节奏，再产生角球、罚牌和时间线。任何推荐若与统一锚点冲突，必须降级为“观望”而不是强行输出。

五个联赛分别校准主场优势、平均进球、角球和罚牌基线，禁止把英超参数直接用于法甲或意甲。

## 历史统计与回测

历史中心明确分为两类：

- `真实赛前推荐`：比赛开赛前实际保存的推荐，可用于公开命中率。
- `模型历史回放`：使用历史赛果和当时可获得的结构化特征重新运行模型，只用于模型评估，不伪装成当时真实发布的推荐。

只有状态为完场且结果经过两个结构化来源核验的比赛才参与结算。未开赛、延期、取消和结果待核验比赛不得计入分母。

回测维度包括联赛、赛季、比赛日期、玩法、置信度、赔率区间和主客队强度差。比分同时统计精确命中、Top3 命中、胜平负方向命中和平均绝对进球偏差。

## 错误处理

- 单个联赛数据源失败时继续展示其他联赛，并显示该联赛最后更新时间。
- 主数据源失败时使用带来源时间的缓存，不把缓存标成实时数据。
- 找不到比赛 ID 时返回 404，禁止回退到列表第一场。
- 盘口缺失时显示“暂无可验证盘口”，模型基线不得伪装为真实盘口。
- 积分榜和赛果冲突时保留两个来源证据并停止结算，等待下一次核验。

## 测试与验收

1. 五个联赛均能返回当前赛季完整比赛、积分榜和至少一场分析。
2. 所有比赛时间统一显示北京时间，并保留 UTC 原值用于匹配。
3. 切换联赛、赛季和场次后，页面所有区域都对应当前比赛。
4. 完场比赛显示实际赛果和保存的赛前推荐，不重新生成赛前预测。
5. 胜平负、比分、让球、大小球、角球、罚牌和模拟结论通过一致性校验。
6. 历史统计只结算完场比赛，并能按五个联赛分别核对样本数。
7. 世界杯不出现在比赛接口、页面筛选和有效历史统计中。
8. 本地首页、赛事、积分榜、分析、历史和回测接口全部通过自动化检查。
